# План: расширение Chrome «Wingspan Helper» для BGA

English version: [plan.md](plan.md).

Движок готов и сверен на двух реальных партиях (см. «Модуль подсчёта очков»).
Осталась обвязка. Этот документ — план обвязки: архитектура, этапы, риски.

Решения, зафиксированные до начала:

| Вопрос | Решение |
|---|---|
| Форма UI | плавающая оверлей-панель поверх страницы BGA |
| Когда считать | автоматически + режим наблюдения (считаем и на ходе соперника) |
| Что показывать | топ-3 хода с приростом в ОП и однострочным обоснованием |
| Код | пишем с нуля в отдельной сессии; движок переносим как есть |

## 1. Где живут данные и почему это определяет архитектуру

`gameui` — объект **страницы**, а не расширения. Контент-скрипт в изолированном
мире его не видит: там своя копия `window`. Обратное тоже верно и тоже важно:
в MAIN-мире `chrome.runtime` не определён, то есть скрипт, который видит `gameui`,
не может сам поговорить с расширением. Отсюда вся остальная схема — мост
на `window.postMessage` между двумя мирами не украшение, а единственный способ.

```
┌─ вкладка boardgamearena.com ────────────────────────────────────────┐
│                                                                     │
│  MAIN world (мир страницы)          ISOLATED world (мир расширения) │
│  ─────────────────────────          ─────────────────────────────── │
│  видит gameui, dojo                 видит chrome.storage, chrome.*  │
│  НЕ видит chrome.*                  НЕ видит gameui                 │
│                                                                     │
│  collector.js                       ui.js                           │
│   • collectState(gameui)             • движок: mat/scoring/evaluate │
│   • подписка на нотификации          • панель в Shadow DOM          │
│   • heartbeat-страховка              • настройки, вес-профили       │
│           │                                    ▲                    │
│           └────── window.postMessage ──────────┘                    │
│                   {source:'wsh-page', seq, state}                   │
└─────────────────────────────────────────────────────────────────────┘
                              │ chrome.runtime (только настройки/команды)
                              ▼
                    service worker sw.js — тонкий
```

**Движок считает в ISOLATED, а не в MAIN.** Так код расширения не попадает в
глобалы страницы, доступен `chrome.storage` для весов и настроек, и границу
пересекает только JSON-снимок. Цена — сериализация состояния на каждое обновление;
она копеечная (снимок — единицы килобайт).

### Фреймы

Игра на BGA бывает в двух видах: как содержимое `#gameIframe` на `tableview?table=…`
и как самостоятельный документ по прямой ссылке `/<ver>/wingspan?table=…`.
Поэтому оба контент-скрипта ставим с `all_frames: true`, а панель рисует **только тот
фрейм, в котором нашёлся `gameui`**. Остальные экземпляры молча выходят.
Дополнительная проверка `gameui.game_name === 'wingspan'` — чтобы не оживать на других играх.

## 2. Состав пакета

```
wingspan-helper-ext/
  manifest.json
  src/
    page/collector.js        ← MAIN: collectState + подписки + мост
    ui/boot.js               ← ISOLATED: приём снимков, оркестрация
    ui/panel.js              ← отрисовка панели (Shadow DOM)
    ui/panel.css
    ui/format-ru.js          ← формулировки ходов словами BGA
    engine/                  ← как есть из wingspan-helper
      mat.js  scoring.js  evaluate.js  page-state.js
      data/birds.json  data/bonus.json      (fallback: обычно берём со страницы)
    shared/protocol.js       ← имена сообщений, версия протокола
  sw.js                      ← иконка, горячая клавиша, badge
  options.html / options.js  ← веса, режимы, диагностика
  build.mjs                  ← esbuild: engine+ui → один classic-script бандл
  icons/
  test/                      ← существующие Node-тесты и fixtures
```

**Почему нужен build.** Контент-скрипты — классические скрипты, `import` в них не
работает. Движок при этом хочется держать в ESM, чтобы Node-тесты гоняли ровно тот же
код. Решение — `esbuild --bundle --format=iife` в два файла: `page.bundle.js` и
`ui.bundle.js`. Одна команда, никакого фреймворка.

### Черновик манифеста

```jsonc
{
  "manifest_version": 3,
  "name": "Wingspan Helper (BGA)",
  "version": "0.1.0",
  "minimum_chrome_version": "111",          // world:"MAIN" в манифесте — с Chrome 111
  "permissions": ["storage"],
  "host_permissions": ["https://*.boardgamearena.com/*"],
  "background": { "service_worker": "sw.js" },
  "action": { "default_title": "Wingspan Helper" },
  "commands": {
    "toggle-panel": { "suggested_key": { "default": "Alt+W" }, "description": "Показать/скрыть панель" }
  },
  "content_scripts": [
    { "matches": ["https://boardgamearena.com/*/wingspan*",
                  "https://*.boardgamearena.com/*/wingspan*",
                  "https://boardgamearena.com/archive/replay/*",
                  "https://*.boardgamearena.com/archive/replay/*"],
      "all_frames": true, "run_at": "document_idle",
      "world": "MAIN",     "js": ["page.bundle.js"] },
    { "matches": [ /* тот же список */ ],
      "all_frames": true, "run_at": "document_idle",
      "world": "ISOLATED", "js": ["ui.bundle.js"] }
  ]
}
```

Разрешений минимум: ни `tabs`, ни `scripting`, ни `activeTab` не нужны — вся работа
идёт из контент-скриптов. `storage` — только под настройки и веса.

Три места, где легко ошибиться:

- **Голый домен и поддомены перечисляем оба.** `*.boardgamearena.com` формально
  описан как «поддомены»; проверять на практике дороже, чем добавить вторую строку.
  Путь в match-паттерне сопоставляется вместе со строкой запроса, поэтому
  `/*/wingspan*` ловит `/8/wingspan?table=123`.
- **`world: "MAIN"` в манифесте появился в Chrome 111** — отсюда
  `minimum_chrome_version`. Перед сборкой стоит перепроверить по текущей документации.
- **К скрипту в MAIN-мире применяется CSP страницы.** Никакого `eval`, никаких
  инлайновых вставок в коллекторе; если BGA ужесточит CSP, ломаться будет именно он.

## 3. Протокол моста

Односторонний поток снимков + редкие команды назад.

```
page → ui   { source:'wsh-page', v:1, type:'state', seq, stable, state, db? }
            { source:'wsh-page', v:1, type:'error', where, message }
ui   → page { source:'wsh-ui',   v:1, type:'pull' }        // ручное обновление
```

Дисциплина безопасности: у получателя проверяем `event.source === window`,
`event.origin === location.origin` и `data.source`. Префикс `wsh-` — чтобы не
пересечься с собственным postMessage-трафиком BGA между шеллом и iframe.

**Справочник карт передаём один раз.** `gamedatas.birds` — это ~180 карт, гонять их
на каждом ходе незачем. Коллектор считает короткий хеш набора и шлёт `db` только
когда UI отвечает, что такого хеша у него нет. Дальше в снимке — id, а не объекты.

## 4. Когда пересчитывать

Два независимых источника событий, оба нужны:

1. **Нотификации BGA** — `dojo.subscribe` на список из документа «чтение состояния»
   (`playBird`, `gainFood`, `layEggs`, `setCube`, `refillTray`, `updateGoalData`, …).
   Основной канал, реагирует мгновенно.
2. **Heartbeat 1 с** — дешёвая проверка «изменилось ли»: хеш от `gamestate.name`,
   активного игрока, счётчиков кубиков и корма. Страховка на случай, когда BGA
   обновит игру и переименует нотификации. Без него молчаливая поломка выглядит
   как «панель залипла».

Поверх — дебаунс 300 мс и жёсткое правило из документа о подсчёте: **пока
`state.name` начинается с `process`, снимок нестабилен** — не считаем и не
перерисовываем цифры, показываем прошлый результат приглушённым.

Ничего в странице не патчим и не переопределяем: только чтение и подписка.
Это и требование к самим себе (не ломать игру), и главный способ пережить
обновления клиента BGA.

## 5. Панель

Shadow DOM на `div` в конце `body`, `position: fixed`, свой z-index.
Shadow-корень нужен не для красоты: CSS BGA агрессивный, без изоляции панель
поедет на первом же обновлении темы.

```
┌──────────────────────────────────────────────┐
│ Раунд 3 · ход 2/6   Вы 34 : 29   ●●○○  [⟳][—]│   стабильно / считаем…
├──────────────────────────────────────────────┤
│ 1. Степь — положить 3 яйца          +4.6 ОП  │
│    Цель раунда «яйца в чашах»: 4→7, выходите │
│    на 1-е место. Кубик последний.            │
│                                              │
│ 2. Сыграть птицу: Зимородок → Болото, кол.2  │
│                                     +3.1 ОП  │
│    6 ОП минус 1 яйцо, но ряд карт ещё пуст.  │
│                                              │
│ 3. Лес — взять 2 корма               +1.2 ОП │
├──────────────────────────────────────────────┤
│ Цели: R3 «яйца в чашах» 4 (2-е) · R4 ждёт    │
│ Бонус: Анатом 5 птиц → 7 ОП (максимум)       │
│ Соперник: 2 кубика, 8 карт, 5 корма          │
├──────────────────────────────────────────────┤
│ ⚠ Синее поле целей не поддерживается          │
└──────────────────────────────────────────────┘
```

Правила подачи:

- Названия действий — **словами BGA** («Положить яйца», «Взять еду», «Взять карты
  птиц», «Сыграть птицу»), чтобы совет читался как указание на кнопку.
- Число рядом с ходом — прирост `V(после) − V(до)` из оценщика, а не абсолют.
  Читается как «сколько этот ход добавил».
- Обоснование — одна строка. Место в панели дороже полноты.
- Всё, что оценщик знает неточно, помечается: «оценка способности по категории»,
  «рука соперника смоделирована», «цель не распознана».
  Молчаливого нуля быть не должно ни в одном месте.
- Перетаскивание и сворачивание, позиция и размер — в `chrome.storage.local`.

### Два режима

**Совет** (по умолчанию): панель считает и показывает топ-3, когда
`stable && myTurn && gamestate.name === 'playerNormalTurn'`.

**Наблюдение**: считает всегда. На ходе соперника показывает оценку позиции,
прогресс по целям у обоих, что успевает соперник оставшимися кубиками и к чему
готовиться на свой ход. Переключатель в шапке, состояние запоминается.

### Под-решения

Отдельный класс подсказок, который легко упустить: игрок часто стоит не перед
«какой ход сделать», а перед диалогом внутри хода. Стейт-машина их называет прямо:

| Стейт | Вопрос | Что советует панель |
|---|---|---|
| `playerGainFromFeeder` | какие кубики взять | корм под конкретные карты руки |
| `playerPowerBrown/White/Pink` | применять способность | стоит ли, и на какую птицу |
| `playerDiscardBird` / `playerDiscardBonus` | что сбросить | наименьшая потеря в ОП |
| `playerTakeCardSpecial` | какую карту из лотка | по вкладу в позицию |
| `playerInitialDiscard` | стартовая рука | ключевой момент партии |

В этих стейтах панель отвечает **на текущий вопрос**, а не на общий «что делать».
Стартовый сброс — вообще отдельная мини-задача оценщика: пять карт, две бонус-карты,
выбор корма; вклад в результат больше, чем у любого одного хода в середине партии.

## 6. Этапы

Каждый заканчивается проверяемым результатом. Архивный реплей #906782034 —
рабочий полигон: те же объекты, что в живой партии, можно перематывать.

| # | Этап | Готово, когда |
|---|---|---|
| **M0** | Каркас: манифест, два мира, мост, панель-заглушка | на реплее панель пишет «Раунд 3, pagyew 34 : Exixel 29» |
| **M1** | Живое состояние: `collectState`, `validateState`, `stable`, подписки + heartbeat | перемотка реплея от начала до конца — панель обновляется на каждом ходе, ни одного снимка с `undefined` в лотке |
| **M2** | Подсказка: движок в UI, топ-3, русские формулировки | на ходе 122 партии #906484481 первым идёт «Степь — положить 3 яйца» (совпадает с `test_position.js`) |
| **M3** | Режим наблюдения + под-решения | панель ведёт прогресс по целям, совпадающий с `gamedatas.goals`, и отвечает на диалог выбора кубиков |
| **M4** | Отладочный контур: кнопка «снять снимок» → JSON | снимок из живой партии сразу проходит `check-game.js` как новый fixture |
| **M5** | Настройка весов `evaluate.WEIGHTS` на архивных партиях | измерена доля совпадений с ходом сильного игрока (top-1 / top-3) на выборке реплеев; после настройки она выросла |
| **M6** | Полировка: options, горячая клавиша, иконки, README, сборка | ставится из zip в `chrome://extensions` в режиме разработчика на чистом профиле |

M4 стоит раньше M5 намеренно: настраивать веса не на чем, пока нет дешёвого способа
превращать живые партии в фикстуры. Кнопка «снять снимок» — это и есть станок,
который производит материал для M5.

**Запись всей партии.** Массовая версия M4: кнопка панели «Начать запись игры»
пишет каждый снимок всей партии и скачивает один JSON-файл, когда
`gamestate.name` доходит до `gameEnd`, либо по ручной остановке. Формат хранит
`src/ui/recorder.js` (чистые, покрытые тестами функции), `boot.js` подключает его
к `chrome.storage.local`, чтобы перезагрузка вкладки посреди партии не теряла
запись, а продолжала её. Материал предназначен для передачи целой партии в LLM
на анализ, а не только для фикстур.

## 7. Риски

**Правила BGA.** Пользовательское соглашение прямо запрещает применять «устройства
или программы, отличные от предоставленных BGA», чтобы извлекать или изменять
содержимое сайта. Расширение под это описание попадает — независимо от того, что
оно только читает и ничего не кликает. Практический вывод, который стоит принять
осознанно: полигон — архивные реплеи и тренировочные партии; в рейтинговых играх
против людей это риск для аккаунта; в Chrome Web Store такое не публикуют.
Автокликов не делаем ни в каком виде — это отделяет помощника от бота и по сути,
и по последствиям.

**Обновление клиента BGA** ломает чтение состояния. Смягчение: все чтения в
try/catch, `validateState` на каждом снимке, при непонятной структуре — честное
«не смог прочитать позицию» вместо неверного совета; heartbeat ловит случай, когда
переименовали нотификации; фикстуры в тестах фиксируют формат.

**Анимации** отдают наполовину обновлённую модель. Смягчение уже есть — флаг
`stable` и запрет считать в `process*`-стейтах.

**Синее поле целей не реализовано** — таблицы очков нет в клиенте. Панель должна
это показывать явным баннером, а не выдавать заниженную оценку. Закрывается одной
партией на синем поле.

**Неполная информация**: рука соперника и его бонус-карта скрыты. Оценщик
моделирует их усреднённой птицей — значит, оценка позиции соперника систематически
менее точна, чем своей. Панель это подписывает.

**Способности птиц оцениваются по категории** — главный источник неточности внутри
самого движка: сильная и слабая птица одной категории получают одинаковую цену.
Отдельная работа после M5: расписать вручную 20–30 самых влияющих карт.

**Производительность**: перебор всех рядов и всех розыгрышей на каждое событие.
Смягчение: дебаунс, кэш результата по хешу состояния, счёт только в стабильных
снимках. Если станет заметно — вынести оценщик в Web Worker (не в service worker:
MV3 его выгружает, состояние там держать нельзя).

## 8. Что решить до первой строки кода

1. **Профиль для разработки.** Ставить расширение в отдельный профиль Chrome —
   отладка на реплеях не должна идти из-под аккаунта, которым играешь в рейтинге.
2. **Язык интерфейса BGA.** Формулировки кнопок берём из русского клиента;
   если играешь на английском — строки нужно вынести в один словарь сразу, а не потом.
3. **Куда класть проект** — папка на компьютере, которую подключим к сессии, чтобы
   писать код прямо туда и не гонять архивы.
4. **Нужен ли режим «после хода»** — показывать не совет до хода, а разбор после:
   слабее как помощь, но полностью снимает вопрос о честности игры.

## 9. Следующий шаг

Начинать с M0 + M1 в одной сессии: каркас без движка бессмысленно проверять, а
связка «мост + живое состояние на реплее» уже даёт всё, на чём стоит остальное.
Перед стартом — подключить папку проекта и положить туда `wingspan-helper`.
